# aips-chronon Access

This page describes how folks supporting the aips-chronon can gain the appropriate access. This could be Site Reliability Engineers, Prod Support, or Developers and QA folks supporting the application.

> INSTRUCTIONS (REMOVE BEFORE COMMITTING)
>
> It is recommended that documentation describing how to obtain access to support your service exist in your repository alongside your codebase, but not required. Not only does documentation that lives alongside code have the greatest chance of being maintained, but also it is much more accessible because OpsLevel surfaces Markdown files in it's UI.
>
> You may link to content in Confluence or Google Docs instead if that works better for you.
>
> Please describe all access required and how to submit access requests for everything from being able to fix a bug all the way through to being able to view operational dashboards etc. Basically, any access you need to be able to fix or enhance the service, or being able to respond when it's broken in production should be in scope here.
