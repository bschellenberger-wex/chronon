# aips-chronon Architecture

This page describes the architecture within which the aips-chronon service fits within. It is intended to assist maintainers of the service, Site Reliability Engineers and folks in Prod Support alike.

> INSTRUCTIONS (REMOVE BEFORE COMMITTING)
>
> It is recommended that architecture documentation exist in your repository alongside your codebase, but not required. Not only does documentation that lives alongside code have the greatest chance of being maintained, but also it is much more accessible because OpsLevel surfaces Markdown files in it's UI.
>
> You may link to content in Confluence or Google Docs instead if that works better for you.
>
> We would strongly encourage the use of [Mermaid.js](https://mermaid.js.org/intro/) for your diagrams which GitHub will render for you. Human readable declarative diagrams that you can diff... what's not to love!
>
> We would strongly encourage the use of [Architecture Decision Records (ADRs)](https://github.com/joelparkerhenderson/architecture-decision-record). [Michael Nygard's template](https://github.com/joelparkerhenderson/architecture-decision-record/tree/main/locales/en/templates/decision-record-template-by-michael-nygard) in particular is recommended because it is lightweight.
